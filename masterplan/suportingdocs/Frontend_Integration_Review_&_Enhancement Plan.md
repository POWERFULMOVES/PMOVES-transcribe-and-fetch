# Frontend Integration Review & Enhancement Plan  
*(For inclusion in `docs/ui_enhancement_plan.md`)*

---

## 1. **Current State: Fetch Page & Related Data Browsers**

### **A. Data Sources**
- **Supabase:**  
  - Used for persistent, queryable history (e.g., `fetch_history`, `transcriptions`, `downloads` tables).
  - [Supabase Infinite Query Hook](https://supabase.com/ui/docs/infinite-query-hook) is already integrated for paginated, filterable data fetching.
- **Backend File System:**  
  - Unified via `/api/list-workspace` and `/api/app-config` endpoints.
  - All files (transcriptions, downloads, fetches, uploads) are organized under `WORKSPACE_ROOT` and `SUBFOLDERS`.

### **B. UI Patterns**
- **Tabs:**  
  - E.g., Fetch page has “Fetch New Content” and “Fetch History” tabs.
- **Forms:**  
  - Advanced options for both Jina and crawl4ai engines.
- **History Tables:**  
  - Paginated, filterable, and sortable using Supabase Infinite Query.
- **Content Viewer:**  
  - Displays fetched/transcribed/downloaded content, with support for markdown, PDF, and raw/structured data.

---

## 2. **Integration Opportunities & Recommendations**

### **A. Unified “Browser” Components for Each Data Type**
- **Pattern:**  
  - Each main data type (Transcriptions, Fetches, Downloads, Uploads) gets a dedicated “browser” page/component.
  - Each browser:
    - Uses Supabase Infinite Query for database records.
    - Uses `/api/list-workspace` for file/folder browsing.
    - Allows cross-browsing (e.g., view transcriptions from downloads page).

- **Benefits:**  
  - Consistent UX across all data types.
  - Easy to add new data types in the future.
  - Users can always see both the database record and the actual file.

### **B. Folder/Workspace Navigation**
- **Show the actual folder structure** (from `/api/list-workspace`) in a sidebar or modal.
- **Allow users to:**
  - Browse by folder.
  - Filter by data type (e.g., only show markdowns, only show PDFs).
  - Select a folder as the “active” location for saving or viewing.

### **C. Supabase Table Integration**
- **For each data type:**
  - Use the Infinite Query Hook to fetch and display records.
  - Support filtering, sorting, and pagination.
  - Show metadata (title, date, type, status, etc.).
  - Link each record to its file in the workspace (if applicable).

### **D. User-Configurable Folders**
- **Let users change the active folder** for saving or browsing.
- **Persist their choice** in local state, Redux, or Supabase user preferences.
- **Always default to backend config** if no user preference is set.

### **E. Cross-Data-Type Browsing**
- **On any browser page,** allow the user to:
  - Switch to another data type (e.g., from Fetches to Transcriptions).
  - See related files/records (e.g., view the markdown generated by a fetch, then see the transcription of that markdown).

### **F. Modern UI/UX Enhancements**
- **Use Supabase UI components** where they offer advantages (e.g., data tables, file upload, authentication).
- **Standardize forms, feedback, and navigation** across all pages.
- **Ensure accessibility and responsiveness**.

## 3. **Detailed Integration Steps**

### **A. Refactor Each Data Page**
- **Transcribe, Fetch, Download, Upserter, Vector Search:**
  - Import and use `useAppConfig` to get folder structure.
  - Use Infinite Query Hook for Supabase data.
  - Use `/api/list-workspace` for file/folder browsing.
  - Add UI for switching folders and data types.

### **B. Create a Shared “WorkspaceBrowser” Component**
- **Features:**
  - Tree/list view of folders/files.
  - Filter by data type or file extension.
  - Click to view file or open related database record.
  - Option to set as “active” folder for saving.

### **C. Enhance History/Results Tables**
- **Add columns for:**
  - File path (relative to workspace root).
  - Links to open file in browser or download.
  - Status, type, and other metadata.
- **Enable actions:**
  - View, re-fetch, re-transcribe, delete, etc.

### **D. Cross-Linking**
- **From any record,** provide links to:
  - The file in the workspace.
  - Related records in other tables (e.g., fetch → transcription).

### **E. User Preferences**
- **Store user’s last-used folder/data type** in local storage or Supabase.
- **Restore on page load** for a seamless experience.
